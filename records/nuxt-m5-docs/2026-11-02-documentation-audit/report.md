用户要求全库扫描、优先高风险，随后要求在文档仓库建立人工审核issue，并把依据与修改方案写清楚。目标是让审核人能逐项定位原文、检查独立来源、判断是否成立并执行最小修订。

- 最初扫描5,899份受版本控制的中英日Markdown文档；检查站内路径、目录目标、多语言差异、完整代码块和近期高风险内容。
- 使用官方芯片厂商资料、公开原理图、固定提交的Arduino/MicroPython库作交叉依据。知识检索与待审文档同源时不当作独立证明。
- 发布前获取远端最新文档基线`47ab6d5115713ffc71ea6ae5ef4dba572fe2c5ac`并复核相关路径。源码工作区未修改；新提交增加/改动的无关页面未伪称已逐篇完成设备验收。
- 已读取目标跟踪系统的全部现有issue，只有一个无关的Basic规格问题，未发现本批同主题重复工单。项目无预设标签，未猜测负责人或里程碑。

本批包括引脚映射、Arduino API与控制流、数据来源和单位、器件与成品规格混用、错链/空页、代码粘贴和翻译破损，以及明确标为待核实的固件兼容性与电气语义问题。具体原文、固定SHA源码依据、最小修改和验收清单见12份工单证据包。

## 修改与验收方案

每份工单均分开列出可确认的文字/API不一致与待设备确认的运行后果。修复以最小改动为原则，涉及三语的统一更新。API例程应固定库版本并完整编译；功能声明按相同实现路径补硬件或有效虚拟设备证据；电气、RF等物理性能只有实测后才能声明。

## 发布授权与限制

常规发布门槛要求可执行同路径验证。本批尚不满足设备验证层；用户已明确批准本次12份工单以REVIEW/待人工审核发表，所有设备结果保持NOT RUN。此例外不扩展为将来任务的通用权限，也不授权关闭issue、修改源文档或宣称修复完成。

本公开记录只保留公开文档和官方源码链接。内部跟踪系统URL、主机路径、服务端点、设备唯一标识与凭据不入库。公开页面链接是动态内容，固定源文件定位记录提交、路径和行号。

## 风险与回滚

本次不改变固件、硬件或文档正文。若人工审核认定某条不成立，在工单追加依据并调整状态；后续新证据追加独立执行记录，不覆盖本次观察。工单交付状态将在后续提交回填。

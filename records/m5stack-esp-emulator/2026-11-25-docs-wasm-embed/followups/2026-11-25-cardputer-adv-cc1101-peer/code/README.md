# 0043 preview source and replay

The browser diff and temporary 0097 patch are byte-for-byte copies of the source used for the observed private dual-guest run. The Python and Node files are the actual local build, stage, compose, host control, and guest replay helpers. The build and stage helper paths describe a scratch workspace layout. They can be adapted to an independent checkout without carrying local configuration.

## Patch checks

1. In a clean simulator worktree at [915faa6bf9882579e10668c315a5f8e74b2491af](https://github.com/m5agent/m5stack-esp-emulator/tree/915faa6bf9882579e10668c315a5f8e74b2491af), apply [the browser diff](0097-browser-integration.patch) with `git apply --check "$RECORD/code/0097-browser-integration.patch"` and then `git apply "$RECORD/code/0097-browser-integration.patch"`. The diff includes the three focused contract tests.
2. Start from the final **already patched** 0043 QEMU tree. The checked-in lock SHA-256 at that simulator revision is `fe8824d3368543c44451ef380be11faa7484b7802815485299ebb733b1c5c85f`. Prepare the source with that revision's [locked builder](https://github.com/m5agent/m5stack-esp-emulator/blob/915faa6bf9882579e10668c315a5f8e74b2491af/scripts/qemu-wasm-build/README.md), or extract the source from the corresponding-source archive of a verified 0043 run. In an isolated QEMU source copy use `patch --dry-run -p1 -i "$RECORD/code/0097-cardputer-adv-cc1101-peer-preview.patch"` and then the same command without `--dry-run`. The exact browser diff applied cleanly to the stated git index. The QEMU patch applied cleanly to the three files extracted from the locked 0043 source archive and reproduced all three candidate source files byte for byte.
3. For a clean local 0043 build, run `python3 platform/tools/bootstrap_qemu_browser_runtime.py --cache .work/cc1101-control-build --output .work/cc1101-control-runtime --jobs 2` at that simulator revision. Export this control from the unmodified browser source, since the stage script verifies control JS before replacing it.

## Adapting the recorded replay

- [Build helper](build-peer-preview.py). Set `control` and `sdk` to your successful 0043 build cache and its isolated Emscripten SDK. Set `lab` to a new scratch parent with the preview patch and the unmodified/patched three source paths under `peer-source/original` and `peer-source/modified`. The source comparison, object list, response-file hashes and compiled asset identities bind the increment to the control. Use a local directory-copy command in place of macOS clone-copy on other systems.
- [Stage helper](stage-peer-preview.py). Set `repo` to the patched simulator worktree, `control` to the untouched static 0043 export, and `lab` to the build helper's new scratch parent. It updates all three touched JS assets plus runtime and site metadata and pins the temporary preview patch. The original source archive covers the 0043 control.
- [Composer](recompose.mjs). Set its `site` to the compatible reference site with the pinned profile and LittleFS manifest. Obtain the original UIFlow2 v2.5.3 raw base from the official upstream URL in the revision's Cardputer-Adv workbench profile, verify the registry SHA-256, then place it as `cardputer-adv-v2.5.3-base.bin` in the scratch parent. Verify the resulting 8 MiB image SHA-256 `b6255f6af5ad10236380eae09a76b44ca174b5c4de391aef16413bdc590952bd`. Firmware, ROMs and runtime binaries are supplied independently.
- [Guest replay runner](cc1101-peer-pair.mjs). Copy to `.work/cc1101-peer-pair.mjs` inside the patched simulator worktree to preserve its relative contract imports. Point `lab` to the scratch parent and `sourceRoot` to the directory containing the two official pinned examples. Run it using the local Chromium, Playwright and environment variables in the [report](../report.md). It only serves an ephemeral loopback origin and explicitly requires enabling exactly two virtual guests.
- [Host control](check-peer-model.py). Put it in the scratch parent with the patched source under `peer-source/modified` and run with Python 3.12+ and a local C compiler. It is a supplemental host check.

The exact replay scripts pin the historical 0043 WASM and control site manifest. An independent rebuild may have different verified output hashes. If those assertions fail, retain them as evidence of a different build. For a new validation, use a copy of the staging scripts tied to the new independently verified control receipt and report its own runtime, source and browser provenance.

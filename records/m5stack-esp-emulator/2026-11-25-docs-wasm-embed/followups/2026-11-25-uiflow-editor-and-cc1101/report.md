# 复现步骤

从工作台静态导出打开两款设备的浏览器 MicroPython 编程镜像。粘贴每个链接所列的官方原样 Python 文件。记录编辑器同一来宾传输、来宾画面和串口。在按钮等需要物理输入的例程用真实浏览器动作对来宾发送事件。最后正常停止虚拟设备。测试中的编程 SDK 基线均为 UIFlow2 v2.5.3；CoreS3 部分运行使用已有浏览器调度候选。具体固件与运行配置见各条摘要。

- CoreS3 display 例程选择 rotation 0，串口报告 240×320，二维码按文档代码绘制在 x=220、宽 100。实际 320×240 RGB565 上只有边缘二维码条。验收需要目标 UIFlow2 版本在相应方向完整绘制图形。
- CoreS3 speaker 绘出可按的播放圆。点击后尝试从 `/flash/res/audio/poweron_2_5s.wav` 打开官方 WAV，抛出 ENOENT。官方源码包内素材存在。验收需要将同一素材随例程可复现地导入，按下播放并观察真实 guest I2S 与浏览器音频。
- CoreS3 mic 的 25 秒运行停在初始 `label0`，未出现后续录音、回放和完成文案。编辑器未能正常中断，工作台 Stop 正常回收。验收需要导入可知 PCM 输入，原代码处理并回放，随后中断和重新执行可用。
- Cardputer-Adv RF TX/RX 两例可见各自的初态界面，但 12 秒后仍停在 `driver/cc1101.py` 中的 `wait_for_idle` 初始化路径。验收需要在实际虚拟 Cap 接线及数据面中观察发端和收端的已知有效载荷。
- NFC 例程的 v2.5.3 原工作台抛出 `TypeError: unexpected keyword argument 'chip'`。错误出自 `NFCCap` 构造，来宾屏幕也显示错误。验收需要使用与文档配套的 UIFlow2 版本完成原构造和传读取卡。

物理 RF、真实录音和真机 `NOT RUN`。摘要省略私有环境字段。待复核的 SDK 版本不可从上述结论继承。

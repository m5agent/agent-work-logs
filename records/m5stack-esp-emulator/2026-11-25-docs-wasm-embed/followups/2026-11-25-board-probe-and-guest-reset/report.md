# 验证结果

## Cardputer-Adv 原 Arduino 例程

在同一个固件选择与镜像布局上对比发布的浏览器 WASM `96c7f8ba…40d8` 和候选 `9c37ace1…1372`。旧版的 M5GFX 将 ADV 识别成 StampS3。重建加入 GPIO 面板 ID 和内部 I2C 探测，复用面板的真实 read-ID。公开源锁记录版本和补丁顺序。

候选使用未改动的 Display 固件绘出 240×135 变化图形。Keyboard 原固件使用实际浏览器可信按键，画面从 a、ab 到 abc。在新库中，普通 Backspace 不触发该例程监听的 Fn 删除标志。发送 Delete（对应设备 Fn 同层）得到 ab，Enter 将 ab 提交到屏幕。两次均正常退出并释放全部 6 个 Worker。在同一候选，ADV 固定 UIFlow2 用例 69 项通过，K132 原厂菜单和 CoreS3 固定 LVGL 触摸也在各自精确的镜像上通过。正式 Pages 发布待单独验收。

## CoreS3 来宾热复位

在同一个合并工作台导出、固件、运行时配置中完成三个独立来宾。修正后的官方 WDT 例程触发 `mpy_machine_wdt`，产生两条来宾 RESET，串口进入 `RTC_SW_CPU_RST` 后停在 `entry 0x403c8890`，180.7 秒没有新的就绪标志。独立运行 `machine.reset()`，在 131.1 秒窗口复现。宿主 QMP 复位的相同固件约 15.1 秒后可执行新代码。三个会话停止都正常，全部 Worker 回收。来宾热复位停滞的具体芯片状态仍待定位。

## CoreS3 v2.5.5 试点

明确绑定修正后的组合镜像和正常时钟。原图形例程的 320×240 guest 帧二维码解码为 `Hello`。另一次独立运行完整复验原 M5UI Button，来宾真实标签变为 `released`。实际编程编辑器回归 66 项通过。录得两次启动约 19 和 21 秒，属于单机并行研究环境。未替换当前默认 UIFlow2 版本。

脱敏摘要保留固件、WASM 和源哈希、实际输入、输出与清理。省略环境地址及原始完整日志。实际硬件、正式托管发布和未列板型不在观察范围。

# Cardputer ADV 虚拟固件审核复测

## 问题和修复

LukewarmCard ADV (Keypad edition) 1.0 的原审使用通用 A/B 按键。固件发布说明声明 Enter 确认，并通过标点键及 Fn 位置对应四个方向。服务现在识别明确的键位说明，在 Cardputer ADV 原生 QEMU 上使用 Enter 与对应方向输入。显式配置的按键仍可用于定制验证。[固件公开发布](https://github.com/Revolution81/LukewarmCard-ADV/releases/tag/v1.0-keypad-5.6.3)

审核启动后在可用的启动画面上执行交互，再保持同一虚拟设备会话，按约五秒间隔记录状态、串口增量和帧哈希。首帧迟到时继续取证并补做交互。审核通过至少需要 60 秒可用运行观察和各项功能检查。有效运行观察时长使用单调时钟计量。提前退出、采样错误或串口崩溃标记会阻止通过。新的通过提交也校验同一任务与源 BIN 的观察记录。

## 实际执行

| 测试 | 结果 |
| --- | --- |
| 原任务同 SHA 的 Launcher 版，审核后端直接加载为虚拟合并镜像 | 运行 90.008 秒，采样 13 次，画面从黑屏到启动标志，三个输入均由接口接收，标志持续到停止。串口为 225 字节 ROM 输出。 |
| 原 BIN 加 I2S 跟踪 | 运行 65.014 秒，观察到 18 次 RX DMA 注入和随后停用寄存器写入，画面停留在启动标志。 |
| 作者独立直刷版，同一审核后端 | 运行 60.010 秒，串口仍为 225 字节。日志有 I2S RX DMA、BMI270 访问及 TCA8418 初始化，未观察到其后键盘 FIFO 读取和菜单画面。 |
| 同机型参考固件，审核后端 | 在 20.013 秒内捕获到 `LoadStorePIFAddrError`、SYSTIMER 地址 `0x60023048` 和重启提示，显示保持黑屏。 |
| 原 BIN，曾验证过 Cardputer ADV 输入和存储的另一原生 QEMU 构建 | 运行 60.024 秒，`down`、`up`、`ret` 均被接收，应用仍停留在启动标志。 |
| 最终服务复审，LukewarmCard 原快照 | Codex、静态检查和运行观察通过。观察 60.159 秒、采样 13 次。Enter 和四方向均被接收，画面哈希未变化，结果 `SIM_PARTIAL`。 |
| 最终服务复审，EMBER 2.1 对照快照 | 使用已保存启动上下文和 SD 镜像。Enter 后画面变化，继续观察 60.094 秒、采样 13 次，结果 `SIM_VERIFIED`。验证范围为虚拟运行和输入响应。 |

Launcher 版和直刷版的字节不同，分别保留哈希。以上都是 virtual-device validation。按键接收表示设备服务接受了输入请求。应用层证据需要可观察的界面响应或串口状态。启动标志和连续存活满足首帧与运行观察条件，LukewarmCard 的正常使用界面仍未得到验证。参考固件的崩溃证明审核后端存在兼容性问题，LukewarmCard 在启动标志之后的具体阻塞点未定位。

先等待一分钟再执行交互的版本曾让 EMBER 2.1 的 Enter 响应由可见变为无变化。最终顺序在启动阶段保留输入检查，并继续采集完整观察窗口。

## 回滚和边界

如需回滚审核服务，从 [run.json](run.json) 的基础提交恢复服务源码并重新加载对应进程。补丁可用 `git apply --check` 在该提交检查。单元测试通过 `python3 -m unittest discover -s tests -q` 运行。

真实 M5Launcher 安装、物理设备、钱包操作、浏览器后端和 Burner 提交均为 `NOT RUN`。原始服务日志和标识保留在本地。公开证据摘要仅摘录时长、哈希、帧状态、输入和故障标记。

# 固件审核服务恢复记录

## 结果与范围

Grok Bot MultiFace · StopWatch 0.3.0 使用原始 BIN 完成真实 AI 内容审查及同一 StopWatch QEMU guest 的运行复审，最终 `done / SIM_VERIFIED`，没有转人工。判定范围为 **virtual-device validation**，不是硬件测量。单击 A 切换外形、单击 B 切换颜色均有显式 framebuffer 断言。

源 BIN 为 647664 字节，SHA-256 `0b207ba2d2ba11907bb4a3bc58fb6cd2ecc0a8f0db8e847ac50969fded0d720a`；补齐至 16 MiB 的虚拟 flash SHA-256 `f708ad5e7f2b54ed2eb4ae9984cfa893a07088b051993e350f7e2c184baee2b8`。源码基线 `56bbe9f02efc38fe132bd844adae0199ac18dbc9`，修复 `85e6d485644776ef49687a9871050a0fd1c853af`。

复审期间上游 pending 队列为空，因此通过控制面的历史复审入口使用已保存描述和同哈希 BIN；结果不代表当前上游待审状态，也没有上架提交。快照结果在提交入口被明确拒绝，后续取得实时 pending 项时可重新完整审核。

## 根因

1. 后台旧版 CLI 继承模型设置却走不兼容的认证路径。进一步实跑又揭示停用的旧提供方配置，以及个人记忆插件在 SessionStart 拉起嵌套旧 CLI，阻塞真正内容审查。它们都是审核基础设施问题。
2. 原实现把 CLI 执行失败默认映射成内容 `MANUAL`，还将规则检查通过概括为内容通过，掩盖 AI 没有完成的事实。
3. 网络规则未处理否定句和参考链接，把“不含……联网功能”及致谢 URL 当成网络声明。
4. “左键 A”“右键 B”“双击 A”“A+B”未被按键词识别；已有触摸计划时没有补测按键。整帧动画变化也不能证明按键功能。

## 修复

- 服务改用当前原生 CLI、显式模型/提供方；仅审核子进程忽略个人配置并关闭 hooks/插件记忆，保留现有登录认证和只读执行。
- 执行失败有限重试、逐次独立输出；配置错误只尝试明确备用路由。超时终止整个子进程组，避免旧进程与重试重叠；旧 PASS 输出不能成为新结果。
- `ERROR / service_error` 与 AI 实际返回的 `MANUAL` 分开。服务重启中断、worker 未收口也标服务异常，保留运行证据；不能作为内容违规或人工内容判断。
- 网络声明按词边界、句段和否定范围处理，清理参考 URL；离线句不抹掉独立的真实网络功能。
- 触摸和 A/B 独立生成输入计划与门槛。可选串口或 framebuffer 状态断言单列，断言不通过时不会由动画帧变化掩盖。
- 增加限定 RGB/RGBA PNG 的纯标准库断言，记录轮廓变化比例、前景主色、配置和帧哈希；不支持或损坏的图片保持 PARTIAL。
- 历史快照先核对原 SHA/大小，保留原轮次，禁止提交；实时审核可替换快照模式。请求验证参数在入队前校验。

## 验证

31 项回归在 `Python 3.9.6` 通过，覆盖 CLI 重试/旧输出/真实 MANUAL/进程组清理，否定与混合网络描述、按键独立门槛、串口新旧状态、PNG 过滤器及眼睛动画干扰、快照完整性与提交隔离。Python 编译、内联 JavaScript `node --check`、差异检查和针对基线的 `git apply --check` 均通过。

最终真实复审从 `2026-11-06T08:26:17.592989+00:00` 至 `2026-11-06T08:26:39.523894+00:00`，约 21.9 秒；独立 AI 调用一次完成，输入/输出 token 为 20934/82。这是本次耗时记录，不是性能基准。

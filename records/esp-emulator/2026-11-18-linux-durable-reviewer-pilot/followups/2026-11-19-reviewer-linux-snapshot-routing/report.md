# 保存快照执行后端路由复验

## 背景与改动范围

Reviewer 0.30.0 支持按明确的保存快照用例选用受管 Linux。主后端继续提供默认审核路径，路由在单次尝试内固定。目标是使用普通审核入口，证明同一任务在选定后端创建会话、验证棋盘、收集证据并释放资源。

测试使用精确提交的 Reviewer 模块和 macOS 系统 Python 3.9.6。两套 Device Service 均为 1.99.3 并返回与固定发布合约逐字节一致的 OpenAPI。测试用 Darwin 后端有独立状态目录，Linux 后端为同一受监督的无网卡 ARM64 虚拟机。使用原版 Core2 2048 1.0、固定启动依据和归一化 Flash。完整散列见脱敏证据摘要。

## 复验步骤

1. 给单个本地 Reviewer 配置可信的主执行后端和受管 Linux 执行后端。Linux 仅启用 Core2 2048 用例，保留主后端的默认路由。
2. 分别读取主就绪接口 `/api/ready` 与 Linux 就绪接口 `/api/ready/linux-snapshot`。用原版 BIN 和匹配的启动依据登记一条保存快照，经普通 `POST /api/reviews/{job_id}/retry` 发起八步四向拖动。请求身使用 `sourceMode=saved_snapshot` 且关闭提交。
3. 在实际会话运行期间只读核对创建意图、执行后端身份和固件。对每一方向分别从实际屏幕验证移动、合并和合法新增方块，核对审核事件、终态与归档。
4. 等到 Linux 应用会话的停止证据可读、可写 Flash 已释放且租约归零，单独停止并重开 Reviewer。依次检查禁用准入、隔离的不可达配置和恢复实际后端配置，并重新核对同一数据库与历史证据。

## 结果

| 层级 | 状态 | 观测 |
| --- | --- | --- |
| 输入与分区 | PASS | 原版 app-only BIN 为 505,760 字节。审核 ZIP 内 Flash 的应用在 `0x10000` 与输入逐字节相等，归一化镜像与固定启动依据的 SHA-256 均匹配 |
| 路由和生命周期 | PASS | 普通保存快照复审返回 HTTP 202。受管路由事件、运行中的 Linux 会话、创建日志与审核终态相互对应。Darwin 创建会话为零 |
| 屏幕和触控 | PASS | 320 × 240 实际画面，60.047 秒内 13 次观察。用每步的稳定截图独立重算棋盘，上下左右各两次均得到合法变化并出现预期范围内的新增方块，终态为 `done / SIM_VERIFIED` |
| 证据和清理 | PASS | Reviewer ZIP 和停止后 Device ZIP 分别核验 9 个与 7 个清单载荷的 CRC、长度与 SHA-256。两包对应同一会话。设备历史仍可读、可写 Flash 已释放、租约为零。测试启动的 Reviewer 和 Darwin 服务均已退出 |
| 就绪和历史 | PASS | 主后端在四种探测配置下均返回 HTTP 200 与 Darwin 就绪。Linux 依次为启用 200、禁用准入 503、替代目标不可达 503、恢复原配置 200。重读同一 SQLite 文件时一条任务与 17 条事件、证据目录一致，创建意图为零 |

## 验证边界与关闭方式

替代目标不可达的验证只改变独立测试的后端配置，执行前已确认没有活动审核或未解决的创建意图。实际受管 Linux 服务保持运行。活动审核期间的连接中断、旧意图跨进程恢复，以及 Reviewer 0.30.0 在 Linux 上执行 ADV 发音均为 `NOT RUN`。真机、浏览器和常驻部署均为 `NOT RUN`，Burner 未提交。

独立试验清空 Linux 准入列表后保留后端登记和审核历史。此操作仅关闭新的选路。原始会话、端点、进程与创建意图标识从归档省去，保存受控证据的长度、SHA-256 和匹配结果。

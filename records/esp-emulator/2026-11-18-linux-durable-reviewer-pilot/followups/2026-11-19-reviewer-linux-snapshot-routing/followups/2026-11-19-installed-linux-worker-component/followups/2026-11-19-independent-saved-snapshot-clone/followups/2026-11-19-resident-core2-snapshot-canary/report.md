# Reviewer 0.31 首次常驻 Core2 独立快照验证

本轮从真实常驻 Reviewer 的已完成记录发起一次授权的独立保存快照请求，精确源码为 `1151dda034d6ec43dcd8c5ef895ae79e009d088f`（0.31.0）。只发送一次 `POST /api/reviews/{job_id}/snapshots`，返回 `202 / queued=1` 并创建一个独立子任务；没有重放或追加请求。标准审核终态为 `done / SIM_VERIFIED`。

严格要求八次有效移动的额外验收为 `PARTIAL`。两个稳定基线帧相同，第二行只有第三格 4、第四格 2，其余格均空；此时再向右不会产生合法移动。审核器将第一步右移标为 `NOT RUN / no_legal_move`，没有发送输入。后续七次实际输入均通过独立棋盘解码、方向合并与一次合法新方块校验，覆盖上下左右，后面的实际右移通过。该未执行项不记成输入失败，也不计为第八次有效移动。

本次原版应用为 505,760 字节，SHA-256 `41db3680f167565dc3ba06e30493e5bb9d6985ee2c5c9e7706940d003a1fdcaa`，合成 Flash 为 `cd13c9bc7594ea3ad1994b1192d7bdd620ab1e6fa2adb2abf23152ebd80020d8`。Device Service 1.99.3 与 Linux QEMU `1733f511c4528cbd991e673069ecedf261b7043e8302553e050924089ce09bff` 固定；实际运行会话、创建意图及既定 worker 相互匹配。观察持续 60.058 秒、13 次样本，启动与显示通过。

父记录的 SQL 行、126 条事件、377 个文件与 API 详情均与之前相同，before/after 快照逐字节一致。子任务证据独立，原始应用和内容文件与父记录字节相同、inode 不同，旧版本唯一槽仍指向父记录。旧证据没有被覆盖。

Reviewer ZIP 与停止后的 Device Service ZIP 共 16 个载荷通过 CRC、大小和 SHA-256 核验，应用分区保持原版。后续认证导出另核对七个稳定载荷摘要相同；ZIP 容器可因导出元数据而变化，不要求整个 ZIP 字节相同。

验证前后的 worker 与卷绑定相同，保留一个已停止的新会话，工作 Flash 释放，租约和创建意图在本次结束时归零。本次没有在主后端创建会话，未提交 Burner。计数仅描述本次观察窗口，不宣称服务总任务量保持固定。

可复核顺序为固定父记录、原版和运行时，以 `sourceMode=saved_snapshot`、`submit=false` 发起一次独立请求；核对实时来源和普通审核结果，重新解码稳定前后棋盘，再比对父记录与同会话归档。[结构化证据](evidence/resident-core2-canary.summary.json)保存每步结果、棋盘、帧和产物摘要。

验证范围为本次原版 Core2 原生虚拟设备路径。严格八次有效移动仍为 `PARTIAL`；其他板卡、其他固件、浏览器 WASM 和物理硬件均为 `NOT RUN`。常驻配置和历史库存的运维细节保存在内部伴随记录。

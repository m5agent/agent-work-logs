# Reviewer 0.31 独立保存快照验证

保存快照的重复审核需要新的任务与证据目录，同时保留原审核结论。Reviewer `0.31.0`（精确提交 `1151dda034d6ec43dcd8c5ef895ae79e009d088f`）新增独立克隆入口；本轮把前序真实完成的 Core2 2048 记录作为父记录，在已安装的 Linux worker 第三代中执行新的普通干跑。没有重新下载或替换原版应用。

首次请求返回 `202 / queued=1`，新任务与父任务不同；相同键和等价正文返回同一子任务、`202 / queued=0`；相同键的有效正文改动返回 `409`。测试 Reviewer 在空闲时退出并以同一个数据库重启后，重放仍返回原子任务且不创建新会话。数据库保留一个克隆绑定，原版版本的唯一索引仍指向父任务。

父记录的 SQL 行、17 条事件与 49 个文件均与开始前相同，before/after 快照逐字节一致。原记录 API 与旧 Device Service ZIP 一致性另由现场采集器核对；独立复核重新比对了保存的原 ZIP、全部父文件及数据库。子任务的固件与内容文件字节相同且 inode 独立，证据目录分开。

子任务使用 505,760 字节原版，SHA-256 `41db3680f167565dc3ba06e30493e5bb9d6985ee2c5c9e7706940d003a1fdcaa`；Device Service `1.99.3`、Linux QEMU 摘要 `1733f511c4528cbd991e673069ecedf261b7043e8302553e050924089ce09bff` 与启动依据固定。实际运行的创建意图、后端身份、应用分区及同会话归档相互匹配，主后端未创建会话。

子任务终态为 `done / SIM_VERIFIED`，60.042 秒内取得 13 次观察样本。独立读取前后棋盘，八次输入均符合对应方向的合并与一次合法新方块，覆盖四个方向。Reviewer 和 stopped Device Service 的两份 ZIP 共 16 个载荷均通过 CRC、大小和 SHA-256 核验。

执行后工作 Flash 释放、创建意图与租约归零，测试进程退出。随后所有者正常停止第三代来宾，真实停止回调与本代就绪记录匹配，临时角色卸载。326 项本地 Reviewer 测试作为独立代码检查记录，不替代本次来宾证据。

可复核顺序为：固定原版与已完成父记录，调用 `POST /api/reviews/{job_id}/snapshots`，声明 `sourceMode=saved_snapshot`、不提交与独立请求键；再依次重放、改变有效选项、核对父文件和行、完成普通审核、同库重启重放，最后正常关闭来宾。完整字段、输入前后棋盘与摘要见[证据](evidence/independent-snapshot-clone.summary.json)。认证材料及唯一标识不随记录公开。

结论限于本次原版与已声明路径。其他固件、浏览器 WASM、物理硬件及生产快照任务均为 `NOT RUN`。常驻运维记录属于内部层；本记录不以常驻只读回读代替应用验收。

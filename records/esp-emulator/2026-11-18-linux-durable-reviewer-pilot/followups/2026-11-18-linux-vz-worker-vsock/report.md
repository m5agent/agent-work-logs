# Linux Worker 就绪通道的隔离验证

前一轮持久卷冷启动试点已在独立 Linux 来宾内回读旧任务、证据 ZIP 和重新导出的 PCAP。要让宿主审核进程可检查 Worker，需要在保留来宾无网卡的情况下建立控制通道。原试点使用 VirtioFS 和单向串口，无法直接传送该 HTTP 请求。

本次在同版 Linux 6.1.0-50-cloud-arm64 内核上加载对应版本的 VSOCK 核心与 Virtio transport 两个模块。宿主使用签名的 Apple Virtualization framework launcher，配置一个 Virtio socket device 和仅限宿主环回的临时 TCP 监听。来宾桥转发到自身环回的 Device Service，只接受来自宿主 CID 的 `GET /api/v1/worker`。认证由真实 Device Service 完成。桥的请求与响应均设读取上限和超时。试验配置没有来宾虚拟网卡或默认路由。

复现顺序是从同版内核软件包取出摘要中列出的三个模块，制作独立 initramfs，在只读输入卷挂载固定的执行端源码和原运行时，再启动签名的无网卡虚拟机。真实 Device Service 使用独立状态目录及短期控制凭证。等待服务自身健康以及来宾桥报告就绪后，核对宿主监听只绑定环回，顺序发送缺凭证、错凭证、正确凭证、其他路由和写入方法五次请求。核对状态码和 Worker 再关闭来宾桥与 Device Service，等待虚拟机实际停止后重查宿主端口。

正确凭证的返回表明 Worker 正在接收租约、状态新鲜，公开会话创建恢复能力 `review-v1`。同一 Worker 前后处于第 1 代，活动租约始终为零。关停后监听拒绝连接。短期控制凭证在执行后清除。

本次保持独立试验状态，各次已存档的持久卷和常驻进程继续由原配置持有。固件、会话写入、流式证据导出和审核队列接入均为 `NOT RUN`。宿主启动程序在兼容语言模式编译，SDK 的 VZ 对象并发标注警告仍保留，VZ 框架调用串行经主队列。

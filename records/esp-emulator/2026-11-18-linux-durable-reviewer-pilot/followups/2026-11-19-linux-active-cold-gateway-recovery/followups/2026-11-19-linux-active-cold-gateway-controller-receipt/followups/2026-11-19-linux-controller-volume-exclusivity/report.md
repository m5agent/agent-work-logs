# 受信任的 VZ 所有者与恢复状态来源验证

本轮复用固定签名的 VZ 启动器与宿主控制器、无网卡 Linux ARM64、Device Service 1.99.0、Reviewer 0.27.0 和未修改的原版 CardputerDict 0.6.4。当前主分支 `7d18dc02be08c3885ec39de7fa7634e79381b042` 的三个恢复实现文件与实测 Linux 包 `97339c1137e4e8564114e7476ba607f1129fe68c` 的对应文件逐字节相同。只给验证夹具增加了持有屏障、对照启动和字节断言。

1. 启动标准保存快照 dry-run。见到旧来宾 QEMU、已提交的具名网关、活动租约和真实 SNTP 后暂停测试夹具推进，来宾与审核保持运行。
2. 两次以同签名启动器尝试加入同一试验目录和同一状态卷，分别用原路径和目录别名。两次锁文件及卷 inode 相同，竞争者均以 68 退出，未形成第二个来宾或凭据，活动原会话仍运行。
3. 结束持有屏障后由宿主停止旧 VZ，获得真实停机确认。用相同旧 VM incarnation 请求后继接入，或把停机确认副本放到不同卷目录，请求均被宿主控制器拒绝，旧确认内容保持一致，未签发凭据。
4. 在真实后继内核中，构造语法和作用域均匹配的版本 1 凭据。旧 worker、实际会话、launch、网关日志摘要及两个 boot 均吻合。分别从恢复盘内和盘外的符号链接提供该凭据。两次启动都在监听前以退出码 2 拒绝。对比 worker、会话、网关记录、隔离记录、PCAP 及可写 Flash 的 SHA-256，内容均保持一致。
5. 同一后继内核先保留默认无凭据的 HTTP 409 对照。可信宿主用独立的只读挂载发放同一旧会话的凭据后，旧会话进入中断历史，释放可写 Flash 和租约。标准原版重试返回 HTTP 202，最终为 `done / SIM_VERIFIED`。来宾得到 10,605 字节 MP3 缓存及 84,992 字节数字 PCM。

旧证据 ZIP 的 9,259 字节原始 PCAP 与宿主停机后直接提取的文件逐字节相同。旧网关和隔离日志保持一致，四份 ZIP 的 CRC、清单和成员摘要通过。两个所有者 VZ 与本轮转发进程均退出，活动租约归零。Burner 未提交。 [精确摘要](evidence/controller-exclusivity.summary.json)

本轮范围是同一宿主、签名启动器及同一个受控试验卷的独占。跨宿主卷锁、任意路径或快照迁移、真实 Linux 常驻路由和生产固件运行均未执行。生产控制器在签发凭据前仍须确认停止原 VM、卷独占交接及按租约回收宿主侧资源。 [标准冷启动恢复记录](../../report.md)

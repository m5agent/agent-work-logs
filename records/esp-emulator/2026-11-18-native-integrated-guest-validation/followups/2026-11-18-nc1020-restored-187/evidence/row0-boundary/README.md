# NC1020 恢复后的首行边界

两轮原始 ZIP、画面和串口哈希保持原样。独立逐像素复核了三对现有 PNG。
A2 的全部非黑像素恰好是横屏 `x=0,y=15..134` 上的 120 个像素，
RGB 均为 `[189,222,189]`，逐像素与 A1 相同。这是逆时针横屏下的
原生内容第 0 行。A1 的下一行也有 120 个非黑像素，A2 的下一行为黑。
两轮首次心跳均为来宾周期 164,524,339 和 RTC 11:14:55，绘制增量分别为 1 和 0。
[样本与哈希](row0-boundary.summary.json)

固定的发布者源码把第一份帧交给 Core 1 显示任务。应用逐行调用 `cp_lcd_draw`。
该函数先提交 ESP-IDF `esp_lcd_panel_draw_bitmap`，随后用无命令
`esp_lcd_panel_io_tx_param` 等待未完成的颜色传输。完整矩形返回后才增加
`g_disp_draws`。因此 A2 首行颜色已经到达面板，显示任务在首行之后的继续路径有缺口。
现有证据还无法区分首行 DMA 完成通知、首行等待返回与次行提交。

## 下一次受控采样

1. 用同一 K132 档案、冻结运行时、原版应用、留存 Flash 和 FAT32 输入启动独立离线恢复会话。
   先仅启用 `M5SW_SPI_WINDOW_TRACE=1`，记录 `[m5panel-window]`，定位 ST7789 的
   `2A 00 34 00 ab` 内容列区间和首两行 `2B 00 28 00 28`、`2B 00 29 00 29`。
   这些地址含发布者源码中的面板偏移 52 和 40。保持无按钮输入并检查首次心跳及强制帧。
2. 若仍能得到首行停顿，追加独立短窗，用 `[spi-xfer]`、`[gpspi-forward]` 核对
   SPI2 LCD 写命令和每行 240 字节原生 RGB565 负载，用 `[gpspi-irq]`、
   `[gpspi-trace]` 核对传输完成状态和中断清除。必要时用 `[spi-tx]` 还原 FIFO 中的参数。
   先裁剪到首两行，若逐条日志改变复现率，可在隔离诊断构建中用有界内存缓冲收集
   指定 LCD 区间的事件，再在首行结果稳定后导出。来宾固件保持原始字节。
3. 若第 0 行有颜色负载且有完成中断、随后缺少第 1 行窗口，下一证据是停住时
   LCD 任务等待栈与 SPI 总线锁或结果队列。只在稳定停顿后读回，避免影响首次出图。
   若第 1 行已经开始，按窗口、颜色负载和面板像素顺序定位缺失步骤。仅凭控制器中断
   置位无法判定原版驱动已回收事务。
4. 保留 A1 的完整画面作为正常路径对照。同条件诊断也需捕获一次原版完整绘制，
   核对两个地址窗口、各行颜色长度和实际画面后，再比较停顿组。历史同核 LCD
   探针的 960/960 完成可检查追踪解释，原版的跨核归因仍取决于同一原版会话。

追踪方案为 `NOT RUN`。本次仅重读了 A1 和 A2 的已有产物，未再启动来宾。

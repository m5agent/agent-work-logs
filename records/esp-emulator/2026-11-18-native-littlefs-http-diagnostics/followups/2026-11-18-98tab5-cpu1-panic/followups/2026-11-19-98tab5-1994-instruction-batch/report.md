# 复验方法与观察

早先的未调试原版会复位，暂停式只读诊断曾让同一原版进一步读盘。为检验更短的
P4 指令批量会否在不连调试器、不改固件时恢复正常冷启，执行默认、P4 显式
5,000、P4 显式 50,000 三个对照。

## 环境和复现

固定 Device Service 1.99.4 `2e4ecb1037e38a3d5ce47864aa0cfd54b8c2b858`、
官方 esp-emu 1.1.0 macOS arm64 和 Tab5 GT911/ILI9881C 档案。运行时、ROM、
eFuse、C6 伴生固件以及原版与规范化 Flash SHA-256 见
[证据摘要](evidence/instruction-batch-summary.json)。原版 98TAB5 1.3.0
为 9,182,880 字节，校验擦除 OTA 数据和单独 OTA0 的应用身份。

在独立 Device Service 通过 `POST /api/v1/firmware/import` 导入原版，随后
以 `device_id=tab5`、导入的 `firmware_id` 和 `runtime=qemu` 创建
离线会话，使用 `gt911-ili9881c` 和 `native_dsi`。不上传 ELF、不装盘、
不发送输入、不连接运行时自身开启的调试监听。默认轮走标准启动。显式参数两轮
通过隔离的宿主启动适配器，只给原生 P4 调用追加 `--batch-size`，并读回实际
启动参数。C6 始终未传此参数，服务的运行时校验和实际执行文件保持一致。

从创建回复起连续观察约 50 秒，轮询 `/api/v1/sessions/{id}` 的状态和同
会话 fresh PNG，收集 UART 和同次 `/evidence` ZIP，核对 manifest、CRC、
Flash 应用身份和关机后租约。三轮各有一次运行前取帧响应与 24 次 DSI
连接后的取帧响应。公开摘要保留串口 SHA-256、字节数、复位计数和逐字节
比较结论，原始命令行、唯一会话标识与串口留在私有取证存储。

## 结果及边界

| P4 指令批量 | 软件复位 | 完整帧 | 串口字节 |
| --- | ---: | ---: | ---: |
| 默认 50,000 | 26 | 0 | 122,376 |
| 显式 5,000 | 56 | 0 | 257,574 |
| 显式 50,000 | 26 | 0 | 122,376 |

显式 50,000 与默认的完整串口相同，且完全是 5,000 轮的前缀。5,000 轮
在观察窗口内重复更多次相同启动序列，当前有限对照中的原版就绪仍为 FAIL。
三轮无低功耗看门狗复位，实际 core dump 写入失败计数分别为 26、56、26。
无盘检测和应用画面都未到达。未借此测量故障当下的寄存器或指令，当前结果
不能确定缓存根因。后续应在保持原版字节和正常运行的前提下复验有盘、无盘、
应用画面及用户输入，或在上游存在可验证修订时重新比较。

带盘、应用输入、WASM 和真机 NOT RUN。此次复验无生产代码或参数调整。

# ESP Emulator 项目状态与文档收敛报告

## 背景

项目在短时间内连续加入 S3/C6 unified runtime、Core2 HCI BLE、公网网络验证、
SoftAP provisioning、历史存储回收和 Device Service API 演进。实现更新速度
快于总览文档，导致 README、AGENTS、backlog 和部分设备档案同时存在：

- “网络尚未接入 Device Service”的旧结论；
- “最新全矩阵 NOT RUN”的旧状态；
- `qemu-ble` 与 `qemu-unified` 混用；
- NanoC6 已能跑完整无屏板级数据面，但仍标记 `boot-capable`；
- 多处 backlog 复制了已经完成的历史 changelog；
- 网络-only 文档仍在描述已被 QEMU unified 关闭的旧缺口。

## 改动

### 信息架构

- `README.md`：保留入口、当前摘要、设备支持、快速开始和边界；
- `docs/project-status.md`：新增当前设备能力、网络状态、验证快照和风险；
- `docs/project-backlog.md`：重写为只包含未完成事项；
- 专题文档继续负责实现、协议、测试方法和历史调查。

### 状态与运行契约

- 规范 runtime 统一为 `qemu-unified`；
- `qemu-ble` 明确为兼容别名和 radio-specific diagnostic；
- `runtime=network` 明确为诊断/SoftAP lane，不得拼成完整设备 PASS；
- 修正 README 默认容量为 12 global / 8 per-device；
- 修正 AGENTS 中关于 S3/C6、Core2 和 network lane 的旧边界。

### 设备档案

- NanoC6 使用新状态 `headless-ready`，schema、generator 和测试同步；
- StopWatch、StickS3、CoreS3、AtomS3R、Cardputer-ADV、PaperColor、
  PaperMono 的生成验证详情补齐 unified WiFi/BLE；
- Nesso N1 和 NanoC6 补充 public-network 证据说明；
- Tab5 的手工补充内容移到 `README.extra.md`，避免重新生成时丢失。

### 防漂移检查

- `test_generated_device_files_match_source`：生成目录必须与
  `catalog.source.json` 一致；
- `test_docs_consistency.py`：
  - 必需文档存在；
  - Markdown 相对链接存在；
  - 已知旧结论不再出现；
  - 当前状态快照含设备数、矩阵数和 canonical runtime；
  - Device Service Markdown 与 OpenAPI 版本一致。

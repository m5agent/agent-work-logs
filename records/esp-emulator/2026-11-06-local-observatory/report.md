# ESP Emulator 本地虚拟设备实时展示页报告

## 背景

- 来源：用户要求保留既有操作工作台，增加本地服务上的独立实时展示空间。
- 现象或需求：其它入口创建的虚拟设备应自动出现，显示真实屏幕、状态、外设连接和串口；短任务结束后留下可识别的展示痕迹。
- 目标：展示页只读，设备寿命由真实执行入口决定。仅接入同一本地服务；不做静态托管部署或浏览器本地 guest 汇聚。
- 后续约束：屏幕没有鼠标或触控，必须自动选择镜头/设备、展示详情和串口；手动选焦 run-4 不能代替最终无人操作验收。

## 结论

- 状态：`PASS`，限本地无人操作展示功能及声明的宿主合同；最终 run-6 完整 31 项通过，早期失败保留。源码已推送，最终文档全 50 项复跑通过；记录发布由仓库发布脚本完成。
- 关键判断：停止不是成功，黑屏不是失败；同型号阵列不是推断出来的批次；逻辑 64 模型场景不等于 64 个 guest。
- 源码身份：最终交付 [dd2eb35d2e6a909992268089ddc37e27970d4a92](https://github.com/m5agent/m5stack-esp-emulator/commit/dd2eb35d2e6a909992268089ddc37e27970d4a92)，功能提交 [e419a28a9b27](https://github.com/m5agent/m5stack-esp-emulator/commit/e419a28a9b277cbf6a66d983d904566863c38a23)；15 个执行源码文件哈希与最终交付 blob 一致。
- 改动范围：本地展示入口、共享 Three.js 场景、只读数据调度、生命周期索引与 API、契约/验收脚本和相应文档。

## 证据

### 代码或配置

入口为 `/observatory`，工作从其它会话入口创建。观测索引保存有限白名单元数据，
在准入、状态持久化和清理前更新；快照和游标原子读取，增量支持 epoch、分页与缺口重同步。
目录清理后不保留原始串口、屏幕字节或源码。观测库故障标记不完整，不妨碍 guest 停止和资源回收。

页面使用单一 WebGL 场景，按型号整理设备；每台屏幕和输出来源保持同一会话身份。
只读内容请求有界，托管 Preview 的帧和 Unit 状态保持 Run 身份门禁。离场动画只延长展示，
不延长 guest、续租或触发设备操作。串口访问被限制时仅相应详情不可用，不改变 guest 行为。

## 风险与回滚

新增页面与观测索引为本地服务能力，不更改 guest 控制接口或既有工作台入口。
异常时仍保留可见的不完整状态；不能把缺失观察显示为通过。
回滚可针对声明的源码提交移除对应页面/路由/索引接入；保留历史证据，按原服务流程清理自有 guest。
原始可变 Flash、固件/ROM 二进制、完整 HTTP 响应和截图未复制到工作记录仓库。

最终自动版补充：短任务实际寿命 `3.624473 秒`，401 个观察请求均为 GET；全部 14 个自有 guest 进程已消失、活动会话为零。15 个执行源码哈希均匹配，后端三文件与已执行重启补充的哈希相同。该最终时间与旧 run-4 的 3.905601 秒分别保留，不混用。

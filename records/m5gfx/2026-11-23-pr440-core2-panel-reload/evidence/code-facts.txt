6. Why the fix matches issue #438
- The pre-reset observation is a valid "panel was displaying" test because the
  ESP32 EN/RST reset does not reset the panel; the panel is still displaying
  when M5.begin() runs.
- If it was displaying, the reset starts the up-to-120 ms NV reload; the init
  list is now held until 122 ms after the release instead of ~6-32 ms.
- If it was already in Sleep In, a reset in Sleep In has no long reload, so the
  wait is skipped, preserving the power-on/blank-state 32 ms start.
- Once a flagged reset has been attempted, later RDDPM reads are ignored
  (a reloading panel also reads Sleep In), so a retry cannot mistake the
  reloading panel for a safe one.

  attempt + 2 == max_attempts. M5GFX::begin() uses max_attempts = 5, so
  init_without_reset() (use_reset = false) can still reset on attempts 4 and 5

  is only true for the first three attempts.

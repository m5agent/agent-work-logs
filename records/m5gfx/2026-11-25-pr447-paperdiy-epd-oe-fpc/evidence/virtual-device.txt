Both images run the same test program (`code/main/main.cpp`). The program prints the compile-time
`wiring::paperdiy::display_oe` value from the generated M5GFX board data, draws a page, calls
`display.sleep()`, waits 1 s, calls `display.wakeup()`, draws a second page and prints a marker after
each step. The program is built once per M5GFX tree; only the M5GFX component differs.

The single `gdma-link ... lli full` error line appears in both builds at the first flush, before
DRAW1_DONE, and does not prevent the draw or the later sleep/wakeup redraw. It is therefore not
attributable to this diff. It was not investigated further (out of scope; IDF v6.1 is outside the
PR's s3 CI matrix).

## Model boundary

The ET047TC1 QEMU model reproduces the digital scan sequence and black/white endpoints. It does not
model the XOE net, EPD_PWR rail, grayscale waveforms or panel optics, so this run cannot observe
whether G45 was previously toggling the panel. That part of the review rests on the schematic.

## 核对

### 1. A 段：收口正确，产出的是上界不是机制

- 110 ms 窗内任一种 burst 的期望 0.081（列 9.08/h + 轨 2.60/h × 226 × 0.110 s），观测 1，
  Poisson P(≥1) = 0.077；只按轨事件算，期望 0.018、P = 0.018，但这是看到事件类型之后
  才选的零假设。
- 能站住的是上界：1/226 = 0.44%，单侧 95% 上界 2.08%/次停顿。大于约 2%/次的“停顿→轨
  burst”被排除，更小的效应这次看不到。n = 1，事后，不构成机制。
- 与第十三轮预测的形状一致（1 个 ≤ 100 ms、3 个在 400–700 ms、其余自由运行），作者停止
  该设计是对的；继续加停顿数不会改善——1 s 窗把约 10 倍背景装进了比较。

### 2. 读数直方图：不是计数口径，但也不是中性——它否掉了 21–54 ms

- 0/42 单读无法用“自由相位的 24–33 ms 状态 + 24.6 ms 轮询”解释：该模型给出
  66–90% 的单读 episode（T = 33/30/27 ms 分别 0.659/0.780/0.902），0/42 的概率
  为 2.5e-20 / 2.2e-28 / 3.5e-43；T < 24.6 ms 时更是必为单读。
- 要让 0/42 不意外（P ≥ 0.05），状态需持续 ≥ 47.5 ms，约 2 个轮询周期。也就是说 24 ms
  数据把生产路径下的持续时间钉在约 50–100 ms（与中轨 45–135 ms、4 读轨对 72–96 ms 一致），
  而 3 ms 臂只测到 21–33 ms。
- 两条出路：快读**缩短**了上报（读推进锁存；我上轮只排除了“延长”，没排除“扰动”），或者
  轮询与上报拍频锁定。两种都意味着 3 ms 臂是扰动探针，不能当被动观测，其时间不能当作
  生产时序。
- 撤回两个数字：第十三轮的“T = 21–54 ms”与本轮据它推的“24–110 ms 带”。保留的说法是
  “状态跨过 1 个轮询周期、约 50–100 ms”，且这是从读数直方图反推，不是直接测量。

### 3. 静默快读格：不是无力，但缺一格对照的定义

- 0/7，单侧 95% 上界 35%/格；7.7 min 内按 A 段列速率期望 1.08 次（P(0) = 0.34），所以
  “这段本来就安静”是补充信息而非推翻——格只占 1.2 min，其余 6.5 min 也无鬼读。
- 与 6/7（burst 后快读）合并：Fisher 单侧 p = 0.0023；与 B 段 0/3（burst 后仍 24 ms 读）
  合并则指向“列 burst 与快读同时在场才出现中轨第二段”，这也解释了它 50 min 生产里未触发。
- 但第 12 轮同一段文字里既写“No control showed one”，又写“once in a control”。若后者是
  B 段三个 24 ms 对照之一，表就是 6/7 对 1/3，Fisher p = 0.18 而非 0.033。这一格必须澄清。
- 快读若本身扰动状态（见第 2 条），它就不能为“活动期”提供被动对照；这一点作者说得对，
  条件形式只能靠 B 段那三个 24 ms 对照。

### 4. 形状计数：24 ms 单侧 0 与原始表 61/97 冲突，规则覆盖取决于口径

- 原始表：97 次鬼点中 61 次带 x = 0 的点，每帧通常 2 点，逐帧记录的三帧里只有两帧是
  两长边各一点。本轮：24 ms 下两长边 21 帧、单侧 0 帧。两者不可能同时描述同一总体，
  除非口径不同（按点 vs 按帧）或总体不同（早期 6 次 boot 含上传/停顿段）。
- 若那 61 个 x = 0 点伴随 x = 20–358 的内点，则该帧既非单侧也非两长边，两长边规则根本
  不适用，仍只由强度决定——这正是第十三轮 (i) 指出的缺口，现在有了量级。
- 若它们是轨上两点，则 24 ms 下确实存在单侧帧，本轮“0 次”就是漏计。规则覆盖、以及
  “单侧形状强度仍守 24”这句话的分量，都取决于这个分类。

### 5. 应用侧 unknown 语义：方向对，残余是释放延迟没有上界

- 把掉落读之后的扫描当 unknown 而不是 empty，正好闭合“真实按压期间 4 读轨对被当成抬指
  → 双击步”的路径，四条主机测试也覆盖了我要问的三种情形。
- 残余：“抬指计数从最后一次掉落读重启”没有上限。若掉落读以 < 60 ms 间隔持续出现，按压
  就无法释放。观测到的 4 读 episode（约 96 ms）把延迟限制在约 156 ms 内，可接受；持续
  掉落流未测。建议一条主机测试：按住 + 每 40 ms 一次掉落读持续 2 s → 不释放，停止后
  60 ms 释放一次。
- 两长边规则留在应用层是对的；696 对真实最大 693 的 3 计数余量在单点 UI 下无关，但若
  将来进驱动需重新定。

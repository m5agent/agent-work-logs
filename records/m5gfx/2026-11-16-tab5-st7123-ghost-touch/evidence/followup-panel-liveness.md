# 第七轮：上拉态面板不显示，零帧结果作废

- 来源评论：huntson，2026-11-16T13:50:50Z，
  [issuecomment-6918314585](https://github.com/m5stack/M5GFX/issues/418#issuecomment-6918314585)
- 环境：同一台 Tab5，pinned 库（M5GFX `d91077b9`、M5Unified `8530f53`），运行期镜像
  M5Unified#367 的三字节写入
- 证据等级：报告者人工观察的硬件结果（单台、1 次重启、6 次点击）；本记录为
  `code-level` 重读其表格

## 报告者新事实

- 上拉态：屏幕空白；人到机器前按压，0 次按下、0 帧。
- 改回 LCD_RST 驱动后重启：画面恢复，随后 6 次点击一次全部登记。
- 夜间无人看屏，mirror 构建的电量/多次启动结果与 `0x9C` 电源模式读都没发现面板是黑的，
  因此那些零帧不是修复证据。
- 翻转运行仍显示帧跟随该引脚，但同时说明上拉态下这块面板整体不工作，而不是鬼点被修好。
- 未查：二分“好”步进与 develop 构建期间屏幕是否也黑。
- 固件已回到 LCD_RST 驱动（pinned M5Unified 的形态），驱动侧过滤仍在挡鬼帧。

## 由此作废或收窄的结论

1. **翻转表里的上拉行（A2、B3、B4）是“面板不工作”行。** 驱动行是“触摸核在扫描”行
   （帧在流动），但这些行的屏幕是否真的在显示仍未记录。因此“A2→A3 / B3→B2 帧随电平
   停/起”与“帧随面板工作状态停/起”是同一观察，也与 B4 脉冲后黑屏 0 帧同类。第六轮
   回复“帧由驱动电平连续门控、电平就是门”的机制表述撤回；保留的只是“面板工作时每轮
   恰好两帧、恢复在一轮内完成”。
2. **`0x08` 的“跨释放粘滞”证据同样来自面板不工作的行**，其含义只剩“出过坐标帧”的
   相关标记。但 A2/B3 中触摸核仍应答 I2C 并保持 `0x08`，说明上拉态不是被按在复位里，
   而是数字核在、扫描与显示停的中间态（假设）。
3. **`0x9C` 不是显示存活探针**：面板黑着时 DCS `0x0A` 仍读 `0x9C`。上一轮把 `0x9C`
   当“醒着”的推断失效。
4. **更早的零结果失去资格**：develop 的 0 帧、两台上拉/镜像构建的 0/58（ainyan03）、
   二分“好”步进，除非当时记录了画面在刷新，否则只是“面板状态未知”。第三/四轮把
   0/58 称为“真实负结果”需要撤回或降级。
5. **DSI 读抑制（boot C）的解释也变了**：C 在读到 100 帧之后才做 `0x0A` 读，读后 0 帧；
   但“读之后面板是否还被点亮”没有记录，若那次读把面板关黑，则“抑制”等于又一次
   “没有显示流量”，而不是触摸扫描引擎被停。D/E 在驱动态下仍 0 帧，但同样没有画面记录，
   不能排除无关的面板不工作。
6. **仍然站得住的事实**：面板工作时（P4 驱动）确有鬼帧（A1 第 9 轮起、B2 第 4 轮起；
   改动前 4/10 次启动出鬼帧）。上拉态是这块面板的失效模式，不是修复。

## 运行状态分类（建议每次运行都记录）

| 观察 | 状态 | 可否用于鬼点计数 |
| --- | --- | --- |
| 画面在刷新 + 真手指有非零 raw | ALIVE | 是 |
| 画面黑或无真手指读数 | PANEL-DOWN | 否，作废 |
| 两者都未记录 | UNKNOWN | 否 |

## 待办的判别项

1. 每次运行先做存活门禁（画面 + 真手指 raw 表），否则标 `PANEL-DOWN`；把已有零结果
   按此重标。
2. 用门禁重跑二分“好”步进与 develop。预测：黑屏，零帧来自面板不工作而非鬼点消失。
3. 两台（ST7121 / ST7123）复核 #367 上拉态是否都黑；若都黑，#367 合并态是显示回归，
   不只是触摸问题，优先级高于鬼点。
4. 若上拉必然黑屏，停止把上拉当鬼点变量；改在驱动态回答，且解释 C 时必须区分
   “读命令关了显示”与“读命令停了扫描”。
5. 空白态的成因未定位：`0x0F` 在上拉态读 1，只说明高于扩展器输入阈值，不说明达到面板
   reset 的 VIH。用一个万用表量 P4 网络电压即可判别“悬空中间电平”假设，不需要示波器。

## 未覆盖项

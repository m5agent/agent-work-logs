# 第八轮：重启前按压为 0，报告延迟分支关闭

- 来源评论：huntson，2026-11-16T14:01:42Z，
  [issuecomment-6918568617](https://github.com/m5stack/M5GFX/issues/418#issuecomment-6918568617)
- 环境：同一台 Tab5，pinned 库，运行期镜像 M5Unified#367 的三字节（LCD_RST 上拉态），
  屏幕空白
- 证据等级：报告者人工观察 + 逐次按压日志（`hardware validation`，单台）；本记录为
  `code-level` 重读其结论

## 报告者新事实

- 重启前在上拉态黑屏构建上按了中间与两侧边缘多次：0 次按下、0 帧；逐次按压日志开着。
- 该计数走门控后的 `getTouchRaw()`，无强制读在跑；因此“核在扫描但从未置 `with_coord`”
  未被排除。
- 重启后登记的 6 次是新按压，发生在重启后 24–31 s，按下当时逐条记录，不是早先按压的
  延迟上报。
- 黑屏时电源模式读仍为 `0x9C`，再次确认它不是存活探针。
- 新门禁：看屏在画 + 手指非零按下，二者齐备才算一次运行；否则 `panel state unknown`。
- 二分“好”步进待有人看屏时按门禁重跑；本机引脚保持驱动，鬼点工作继续。

## 本轮结论

1. **报告延迟/排队分支关闭。** 重启前按压全部为 0，重启后 6 次是新事件，不存在“上拉态
   缓存、驱动恢复后补报”。上一轮保留的另一分支（host reporting failure / 延迟上报）
   撤回；上拉行只能读作“没有坐标上报”。
2. **表述收窄。** failed-read = 0 且 `with_coord` 未置位，只证明“没有坐标上报”，不能
   证明“核停止扫描”。结合 A2/B3 的 I2C 应答与 `0x08` 保持，上拉态的准确描述是：显示灭、
   数字核在应答、无坐标上报、扫描状态未证实。第七轮“数字核在、扫描与显示停”里的“扫描停”
   降级为“未证实”。
3. **鬼点结论不变。** 手指都报不出坐标的面板不能当鬼点过滤器；帧只在驱动行出现。
4. **门禁两半独立失败。** 未看屏 → `panel state unknown`；看屏但无手指 → `touch path
   unknown`。两者不能合并，否则无手指的零结果会被记成“面板不工作”。

  `qom`/`device_state` 为 false，ST7123 触摸是固件 GDB 邮箱，无 `0x43` 扩展器与 reset

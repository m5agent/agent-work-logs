# 脱敏规则

本仓库同时推送到公开 GitHub，因此**所有内容默认按可公开标准撰写**。任何一条记录提交前
都必须通过本页检查清单。

## 绝不提交

- token、API key、Bearer、Cookie、session 凭据、私钥、密码；
- 内网 URL、内网 IP、内网主机名、服务器路径、端口映射；
- 测试槽 ID、节点 ID、设备 MAC、序列号、RFID EPC/UID、客户单号；
- 客户数据、未公开的物料清单、未发布产品的规格细节；
- 未授权的第三方代码、数据手册全文或固件二进制。

## 可以提交

- 公开仓库的 commit SHA、issue 编号、PR/MR 编号和公开发布版本号；
- 脱敏后的任务 ID、session ID、artifact ID（保留内部可追溯性，不带端点信息）；
- 固件或产物的 SHA256、大小、构建命令和可重建工程；
- 结论性的行为描述、协议帧、错误码和时序；
- 明确标注为 summary 或 redacted 的派生证据。

## 需要脱敏时的做法

1. 保留原始文件的结构和字段顺序，只替换敏感值；
2. 文件名包含 `redacted` 或 `summary`；
3. 正文明确说明删除了什么类型的字段；
4. 记录原始数据的 SHA256、字节数、任务 ID 和 session ID 以供内部追溯；
5. 不得把脱敏文件标记为 raw，也不得暗示它是未经处理的原始输出。

## 替代说法

| 不要写 | 改写为 |
| --- | --- |
| 具体内网地址和端口 | “内部测试端点（未公开）” |
| 设备 MAC 或节点 ID | “被测设备（标识已脱敏）” |
| 内网服务页面路径 | “内部控制台” |
| 内部项目编号前缀（未公开产品） | “未发布产品 Pxxx”（保留编号但确认可公开） |

产品型号编号在已公开发布或本仓库既有记录已使用时可以保留；未发布型号先按“未发布产品”处理。

## 提交前检查清单

- [ ] 全文搜索 `token`、`key`、`secret`、`password`、`Bearer`；
- [ ] 全文搜索 `192.168.`、`10.`、`127.0.0.1`、`.local`、`localhost`；
- [ ] 全文搜索 MAC 形式地址和长十六进制设备标识；
- [ ] 确认所有链接指向公开资源；
- [ ] 确认 JSON 与 Markdown 中没有内嵌凭据或签名 URL；
- [ ] 确认 evidence 文件已按上述规则处理并命名正确。
